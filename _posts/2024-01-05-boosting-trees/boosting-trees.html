Teoria

Boosting

Boosting é outra abordagem para melhorar as previsões de uma árvore de decisão. Similar ao bagging, é uma abordagem geral que pode ser aplicada a muitos métodos de aprendizado estatístico para regressão ou classificação. No entanto, no contexto das árvores de decisão, a discussão de hoje se restringe ao boosting.

Enquanto o bagging envolve criar múltiplas cópias do conjunto de dados de treinamento original usando a técnica de bootstrap, ajustar uma árvore de decisão separada para cada cópia e então combinar todas as árvores para criar um único modelo preditivo, o boosting funciona de forma semelhante, mas com uma abordagem sequencial. Cada árvore é construída usando informações das árvores previamente criadas. No boosting, não há amostragem de bootstrap; em vez disso, cada árvore é treinada em uma versão modificada do conjunto de dados original. Essa abordagem sequencial no boosting geralmente leva a modelos mais poderosos, focados em corrigir áreas onde os modelos anteriores falharam, resultando em melhor desempenho preditivo.

No contexto da regressão, assim como no bagging, o boosting envolve combinar um grande número de árvores de decisão \(\hat{f}^1,...,\hat{f}^B\). O boosting é descrito no Algoritmo 1.

—————————————————————————————————————————————— Algoritmo 1. Boosting para Árvores de Regressão: ——————————————————————————————————————————————

  • Defina \(\hat{f}(x) = 0\) e \(r_i = y_i\) para todos os \(i\) no conjunto de treinamento.
  • Para \(b = 1, 2,...,B\), repita:

  1. Ajuste uma árvore \(\hat{f}^b\) com \(d\) divisões (\(d + 1\) nós terminais) aos dados de treinamento \((X, r)\).

  2. Atualize \(\hat{f}\) adicionando uma versão encolhida da nova árvore:

\(\hat{f}(x) ← \hat{f}(x) + λ \hat{f}^ b(x).\)

  1. Atualize os resíduos,

\(r_i ← r_i − λ \hat{f}^b (x_i).\)

  • Produza o modelo com boost,

\(\hat{f}(x) = \sum_{b=1}^Bλ \hat{f}^ b(x).\)

——————————————————————————————————————————————

A ideia por trás desse procedimento difere da abordagem de ajustar uma única árvore grande aos dados, que pode levar ao overfitting ao ajustar os dados de maneira rígida. O boosting, por outro lado, aprende lentamente. Dado o modelo atual, ajustamos uma árvore de decisão aos resíduos do modelo. Ou seja, ajustamos uma árvore usando os resíduos atuais, em vez do resultado \(Y\), como resposta. Em seguida, adicionamos esta nova árvore de decisão à função ajustada para atualizar os resíduos. Cada uma dessas árvores pode ser relativamente pequena, com apenas alguns nós terminais, determinados pelo parâmetro \(d\) no algoritmo. Ao ajustar árvores pequenas aos resíduos, melhoramos gradualmente \(\hat{f}\) em áreas onde não performa bem.

O parâmetro de encolhimento \(λ\) diminui ainda mais o processo, permitindo que mais árvores de formas diferentes ataquem os resíduos. Em geral, abordagens de aprendizado estatístico que aprendem lentamente tendem a ter um bom desempenho. No boosting, ao contrário do bagging, a construção de cada árvore depende fortemente das árvores já criadas.

Esse processo descreve o boosting de árvores de regressão. O boosting de árvores de classificação segue de maneira similar, mas de um modo ligeiramente mais complexo.

O boosting clássico possui três parâmetros de ajuste:

  • O número de árvores \(B\). Diferentemente do bagging e das florestas aleatórias, o boosting pode ter overfitting se \(B\) for muito grande, embora isso ocorra lentamente, se ocorrer. Usamos validação cruzada para selecionar \(B\).
  • O parâmetro de encolhimento \(λ\), um número positivo pequeno. Ele controla a taxa de aprendizado do boosting. Valores típicos são 0.01 ou 0.001, e a escolha correta pode depender do problema. \(λ\) muito pequeno pode exigir um valor muito grande de \(B\) para obter bom desempenho.
  • O número d de divisões em cada árvore, que controla a complexidade do conjunto de árvores. Muitas vezes, \(d = 1\) funciona bem, o que significa que cada árvore é um “stump”, consistindo de uma única divisão. Nesse caso, o conjunto de stumps do boosting está ajustando um modelo aditivo, já que cada termo envolve apenas uma variável. Geralmente, \(d\) é a profundidade da interação e controla a ordem de interação do modelo boost, já que \(d\) divisões podem envolver no máximo \(d\) variáveis.

Na Figura 1, o boosting foi aplicado a um conjunto de dados de expressão genética de câncer de 15 classes, para desenvolver um classificador que distingue a classe normal das 14 classes de câncer. O erro de teste é exibido em função do número total de árvores e da profundidade de interação \(d\).

Observamos que “stumps” simples com profundidade de interação 1 têm bom desempenho se incluídos em número suficiente. Esse modelo supera o modelo de profundidade 2 e ambos superam uma floresta aleatória. Isso destaca uma diferença entre boosting e florestas aleatórias: no boosting, porque o crescimento de uma árvore específica leva em consideração as outras árvores já criadas, árvores menores são geralmente suficientes. O uso de árvores menores pode auxiliar na interpretabilidade; por exemplo, o uso de “stumps” leva a um modelo aditivo.

XGBoost

XGBoost é um sistema de aprendizado de máquina de código aberto que implementa um algoritmo de boosting de árvores gradiente. O boosting de árvores é uma técnica de aprendizado de máquina que combina várias árvores de decisão para melhorar a precisão de predição.

O XGBoost é um sistema escalável por vários motivos. Primeiro, ele usa um algoritmo de aprendizado de árvore específico para dados esparsos. Dados esparsos são dados em que muitos dos valores são zeros. O algoritmo de aprendizado de árvore do XGBoost é projetado para lidar com dados esparsos de forma eficiente.

Segundo, o XGBoost usa uma técnica de amostragem de quantis ponderada para aprendizado de árvore aproximado. Essa técnica amostra aleatoriamente os dados e as árvores para reduzir o tempo de treinamento.

O XGBoost também é flexível e fácil de usar. Ele suporta uma variedade de funções de perda e funções de penalidade, o que permite que seja adaptado a diferentes problemas de aprendizado de máquina. O XGBoost também oferece suporte a vários mecanismos de regularização, que ajudam a evitar o sobreajuste do modelo.

Algoritmo

O algoritmo funciona adicionando árvores de decisão à um modelo de aprendizado de máquina sequencialmente. Cada árvore é projetada para reduzir o erro do modelo em relação aos dados de treinamento.

O algoritmo de boosting de árvores gradiente pode ser expresso matematicamente da seguinte forma:

\[f(x) = \sum_{t=1}^T \beta_t h_t(x)\] Onde:

\(f(x)\) é o modelo de aprendizado de máquina resultante

\(T\) é o número de árvores no modelo

\(β_t\) é o peso da t-ésima árvore

\(h_t(x)\) é a função de predição da t-ésima árvore

O peso da t-ésima árvore é calculado usando o gradiente da função de perda do modelo em relação aos dados de treinamento. A função de perda é uma medida da diferença entre as previsões do modelo e os valores reais dos dados.

Funções de perda e funções de penalidade

O XGBoost suporta uma variedade de funções de perda e funções de penalidade. A função de perda é usada para medir o erro do modelo em relação aos dados de treinamento. A função de penalidade é usada para evitar o sobreajuste do modelo.

Algumas funções de perda comuns incluem:

Erro quadrático médio \((MSE): L(y,f(x))=(y−f(x))^ 2\)

Erro de erro médio \((MAE): L(y,f(x))=∣y−f(x)∣\)

Erro de entropia cruzada \((CE): L(y,f(x))=−∑_y ylogf(x)+(1−y)log(1−f(x))\)

Algumas funções de penalidade comuns incluem:

Regularização \(L1: λ∑_ tβ_t\)

Regularização \(L2: λ∑_ tβ_ t^2\)

Regularização \(Elastic Net: λ_ 1∑_ tβ_ t+λ_ 2∑_ tβ_ t^2\)

Mecanismos de regularização

O XGBoost oferece suporte a vários mecanismos de regularização, que ajudam a evitar o sobreajuste do modelo. Os mecanismos de regularização mais comuns incluem:

  • Subamostragem de dados: o XGBoost pode subamostrar os dados de treinamento para reduzir o tamanho do modelo.
  • Subamostragem de árvores: o XGBoost pode subamostrar as árvores de decisão para reduzir o tamanho do modelo.
  • Regularização L1 e L2: o XGBoost pode usar regularização L1 ou L2 para reduzir o tamanho do modelo.

Hiperparâmetros

  • tree_depth: Profundidade da Árvore (tipo: inteiro, padrão: 6L)
  • trees: Número de Árvores (tipo: inteiro, padrão: 15L)
  • learn_rate: Taxa de Aprendizado (tipo: duplo, padrão: 0.3)
  • mtry: Número de Preditores Selecionados Aleatoriamente (tipo: inteiro, padrão: ver abaixo)
  • min_n: Tamanho Mínimo do Nó (tipo: inteiro, padrão: 1L)
  • loss_reduction: Redução Mínima da Perda (tipo: duplo, padrão: 0.0)
  • sample_size: Proporção de Observações Amostradas (tipo: duplo, padrão: 1.0)
  • stop_iter: Número de Iterações Antes da Parada (tipo: inteiro, padrão: Inf)

LightGBM

LightGBM é um sistema de boosting de árvores altamente eficiente que foi apresentado por Guolin Ke, Qihang Wang, Wei Chen, Wei Hu, and Tie-Yan Liu em 2017. O sistema é amplamente utilizado por cientistas de dados para alcançar resultados de última geração em muitos desafios de aprendizado de máquina.

O LightGBM apresenta várias inovações que o tornam um sistema altamente eficiente. Uma inovação é o uso de um algoritmo de crescimento de árvore greedy. O algoritmo de crescimento de árvore greedy do LightGBM é projetado para reduzir o número de folhas de uma árvore, o que melhora a eficiência do treinamento.

Outra inovação é o uso de uma técnica de amostragem de gradientes ponderada. A técnica de amostragem de gradientes ponderada do LightGBM amostra aleatoriamente os dados e os gradientes para reduzir o tempo de treinamento.

O LightGBM também oferece vários recursos que o tornam flexível e fácil de usar. O sistema suporta uma variedade de funções de perda e funções de penalidade, o que permite que seja adaptado a diferentes problemas de aprendizado de máquina. O LightGBM também oferece suporte a vários mecanismos de regularização, que ajudam a evitar o sobreajuste do modelo.

Algoritmo de crescimento de árvore greedy

O algoritmo de crescimento de árvore greedy do LightGBM funciona adicionando folhas à um árvore de decisão sequencialmente. Em cada iteração, o algoritmo escolhe a folha que tem o maior ganho de ganho, que é calculado usando a seguinte fórmula:

\(Gain = \sum_{i \in L} G_i\)

Onde:

\(L\) é o conjunto de dados da folha

\(G_i\) é o ganho de informação da i-ésima instância

O ganho de informação é uma medida da diferença entre a distribuição de probabilidade dos dados antes e depois de a instância ser adicionada à folha.

Amostragem de gradientes ponderada

A técnica de amostragem de gradientes ponderada do LightGBM funciona amostrando aleatoriamente os dados e os gradientes para reduzir o tempo de treinamento. A técnica funciona da seguinte forma:

  • Calcule os gradientes dos dados de treinamento.
  • Atribua pesos aos dados de treinamento com base nos seus gradientes.
  • Amostre os dados de treinamento com base nos pesos.

A técnica de amostragem de gradientes ponderada reduz o tempo de treinamento do LightGBM em até 20 vezes sem afetar a precisão do modelo.

HiperParâmetros

  • tree_depth: Profundidade da Árvore (tipo: inteiro, padrão: -1)
  • trees: Número de Árvores (tipo: inteiro, padrão: 100)
  • learn_rate: Taxa de Aprendizado (tipo: duplo, padrão: 0.1)
  • mtry: Número de Preditores Selecionados Aleatoriamente (tipo: inteiro, padrão: ver abaixo)
  • min_n: Tamanho Mínimo do Nó (tipo: inteiro, padrão: 20)
  • loss_reduction: Redução Mínima da Perda (tipo: duplo, padrão: 0)

Prática

Aplicações de cartão de crédito

Os bancos comerciais recebem muitos pedidos de cartões de crédito. Muitos deles são rejeitados por vários motivos, como altos saldos de empréstimos, baixos níveis de renda ou muitas consultas no relatório de crédito de um indivíduo, por exemplo. Analisar manualmente essas aplicações é mundano, sujeito a erros e demorado (e tempo é dinheiro!). Felizmente, essa tarefa pode ser automatizada com o poder do aprendizado de máquina e praticamente todos os bancos comerciais o fazem hoje em dia. Neste projeto, construiremos um preditor automático de aprovação de cartão de crédito usando boosted trees.

Dados

Usaremos o conjunto de dados de aprovação de cartão de crédito do UCI Machine Learning Repository.

  • Veremos que o conjunto de dados tem uma mistura de características numéricas e não numéricas, que contém valores de diferentes intervalos, além de conter várias entradas ausentes. - Teremos que pré-processar o conjunto de dados para garantir que o modelo de aprendizado de máquina escolhido possa fazer boas previsões.
  • Depois que nossos dados estiverem em boa forma, faremos algumas análises exploratórias de dados para construir nossas intuições.
  • Finalmente, construiremos um modelo de aprendizado de máquina que pode prever se o pedido de cartão de crédito de um indivíduo será aceito.

O conjunto de dados também contém valores de vários intervalos. Alguns recursos têm um intervalo de valores de 0 a 28, alguns têm um intervalo de 2 a 67 e alguns têm um intervalo de 1017 a 100000. Além disso, podemos obter informações estatísticas úteis (como média, máximo e mínimo) sobre os recursos que possuem valores numéricos.

Por fim, o conjunto de dados possui valores ausentes, mas que não aparecem na análise exploratória, dos quais cuidaremos nesta tarefa. Os valores ausentes no conjunto de dados são rotulados com ‘?’

Agora, vamos substituir temporariamente esses pontos de interrogação de valores ausentes por NA e transformar caracteres e variáveis lógicas em fatores. Além disso, recursos como Carteira de motorista e Código postal não são tão importantes quanto os outros recursos no conjunto de dados para prever aprovações de cartão de crédito.

Para ter uma noção melhor, podemos medir sua correlação estatística com as variáveis do conjunto de dados. Devemos abandoná-los para criar nosso modelo de aprendizado de máquina com o melhor conjunto de variaveis. Na literatura de Ciência de Dados, isso costuma ser chamado de seleção de variaveis.

Pré-Processamento

Substituímos todos os pontos de interrogação por NA’s. Isso vai nos ajudar no próximo tratamento de valores ausentes que vamos realizar. Uma questão importante levantada aqui é por que estamos dando tanta importância aos valores ausentes? Eles não podem ser simplesmente ignorados? Ignorar os valores ausentes pode afetar fortemente o desempenho de um modelo de aprendizado de máquina. Ao ignorar os valores ausentes, nosso modelo de aprendizado de máquina pode perder informações sobre o conjunto de dados que podem ser úteis para seu treinamento.

Além disso, existem muitos modelos que não podem lidar com valores ausentes implicitamente, como a Análise Discriminante Linear (LDA). Então, para evitar esse problema, vamos imputar os valores faltantes com uma estratégia chamada imputação mediana.

Ainda faltam alguns valores a serem imputados para as colunas 0, 1, 3, 4, 5, 6 e 13. Todas essas colunas contêm dados não numéricos e é por isso que a estratégia de imputação média não funcionaria aqui. Isso precisa de um tratamento diferente. Vamos imputar esses valores ausentes com os valores mais frequentes presentes nas respectivas colunas. Essa é uma boa prática quando se trata de imputar valores ausentes para dados categóricos em geral.

Ainda há algum pré-processamento de dados menor, mas essencial e necessário antes de prosseguirmos para a construção de nosso modelo de aprendizado de máquina:

  • Remover variáveis com 0 de variância, se houver
  • Remover variáveis X12 e X14, com mencionado anteriormente
  • Dimensionar os valores das variáveis para um intervalo uniforme
  • Converter os dados não numéricos em numéricos: fazemos isso porque não apenas resulta em uma computação mais eficiente, mas também muitos modelos de aprendizado de máquina (como XGBoost) exigem que os dados estejam em um formato estritamente numérico
#receita com a fómula e pré-processamentos necessários
receita = recipe(X16~., cc_train) %>%
  step_rm(X14, X12) %>%
  step_zv(all_numeric_predictors()) %>%
  step_impute_median(all_numeric_predictors()) %>%
  step_normalize(all_numeric_predictors()) %>%
  step_impute_mode(all_factor_predictors()) %>%
  step_dummy(all_factor_predictors())

Modelos

Essencialmente, prever se um pedido de cartão de crédito será aprovado ou não é uma tarefa de classificação. De acordo com a UCI, nosso conjunto de dados contém mais instâncias que correspondem ao status “Negado” do que instâncias correspondentes ao status “Aprovado”. Especificamente, de 690 casos, 383 (55,5%) dos pedidos foram negados e 307 (44,5%) foram aprovados. Isso nos dá uma boa referência.

Um bom modelo de aprendizado de máquina deve ser capaz de prever com precisão o status dos pedidos em relação a essas estatísticas.

Primeiro vamos criar as especificações dos nossos 2 modelos:

#especificações XGBoost
xgboost_spec <- boost_tree(mtry = tune(), 
                           trees = tune(), 
                           min_n = tune(),
                           tree_depth = tune(), 
                           learn_rate = tune(), 
                           loss_reduction = tune(),
                           sample_size = tune(), 
                           stop_iter = tune(), 
                           mode = "classification", 
                           engine = "xgboost")

#especificações LightGBM
light_spec <- boost_tree(tree_depth = tune(),
                         trees = tune(), 
                         learn_rate = tune(),
                         mtry = tune(), 
                         min_n = tune(), 
                         loss_reduction = tune(), 
                         mode = "classification", 
                         engine = "lightgbm")

Agora, vamos criar os dados para validação, que serão usados para otimizar os hiperparâmetros e criar um workflow para cada modelo

#dados para validação cruzada, por bootstrap
set.seed(12345)
resample <- bootstraps(cc_train, times = 10, strata = X16)

#workflow XGBoost
xgb_wflow <- workflow() %>%
  add_recipe(receita) %>%
  add_model(xgboost_spec)

#workflow lightGBM
library(bonsai)
light_wflow <- workflow() %>%
  add_recipe(receita) %>%
  add_model(light_spec)

Precisamos, ainda, definir os parâmetros de cada modelo e criar um grid com várias combinações de parâmetros para podemos otimizá-los

#parametros xgboost
xgb_params <- extract_parameter_set_dials(xgboost_spec) %>%
  finalize(cc_train)

#parametros lightGBM
light_params <- extract_parameter_set_dials(light_spec) %>%
  finalize(cc_train)

#grid de parâmetros (30 combinações para cada)
xgb_grid <- grid_latin_hypercube(x = xgb_params, size = 30)
light_grid <- grid_latin_hypercube(x = light_params, size = 30)

Podemos otimizar os parâmetros com o pacote tune. Vou utilizar um método de racing, que depois que um número inicial de reamostragens é avaliado, o processo elimina combinações de parâmetros de ajuste que são improváveis de resultar nos melhores resultados usando um modelo de ANOVA de medidas repetidas.

#biblioteca para processamento em paralelo
library(doParallel)
cores <- parallel::detectCores()
cl <- makePSOCKcluster(cores)
registerDoParallel(cl)

#otimização com tune_race_anova
library(finetune)
xgb_tune_results <- tune_race_anova(object = xgb_wflow, 
                                    resamples = resample, 
                                    grid = xgb_grid,
                                    metrics = metric_set(roc_auc, accuracy))

light_tune_results <- tune_race_anova(object = light_wflow, 
                                    resamples = resample, 
                                    grid = light_grid,
                                    metrics = metric_set(roc_auc, accuracy))

Podemos visualizar como as possíveis combinações de parâmetros que tentamos se saíram durante a “corrida”. Note como economizamos MUITO tempo ao não avaliar as combinações de parâmetros que estavam claramente se saindo mal em todas as reamostragens; só continuamos com as boas combinações de parâmetros.

plot_race(xgb_tune_results)
plot_race(light_tune_results)
